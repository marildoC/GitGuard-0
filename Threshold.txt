PART 2: SOURCEAUTH DEEP ANALYSIS - WHY IT'S UNRELIABLE
================================================================================

OBSERVATION FROM USER TEST:
- sa_states REAL=0.0 L_REAL=0.0 SPOOF=0.0 UNC=1.0 (100% UNCERTAIN)
- This is for a REAL face in live video!
- Overlay shows score=0.50 (neutral) throughout

─────────────────────────────────────────────────────────────────────────────────
ROOT CAUSE ANALYSIS
─────────────────────────────────────────────────────────────────────────────────

SourceAuth uses 3 cues to determine if face is real:
  1. Motion Cue (3D vs planar) - source_auth/motion.py
  2. Screen Cue (phone/display detection) - source_auth/screen_artifacts.py
  3. Background Cue (environment consistency) - source_auth/background.py

THE CRITICAL FLAW (source_auth/fusion.py Line 101-121):

  if not (has_motion or has_background):
      return UNCERTAIN  # ← THIS IS THE PROBLEM

If BOTH motion AND background cues are "unreliable", fusion returns UNCERTAIN.
For YOUR use case (stationary user in front of camera), BOTH cues fail:

─────────────────────────────────────────────────────────────────────────────────
MOTION CUE FAILURE (source_auth/motion.py)
─────────────────────────────────────────────────────────────────────────────────
FILE: source_auth/motion.py

The motion cue returns reliable=False if ANY of these conditions fail:

Line 334: if n_frames < 2:
          → Need at least 2 frames in history
          
Line 350: if span_sec < min_span_sec (0.75s by default):
          → Need 0.75+ seconds of landmark history
          
Line 362: if n_landmarks < min_landmarks (3):
          → Need 3+ landmarks per frame
          
Line 454: if global_motion_mag < min_motion_pixels:
          → CRITICAL: User must PHYSICALLY MOVE THEIR HEAD
          → min_motion_pixels ≈ max(2.0, face_size * 0.01)
          → A stationary user produces ~0 pixels of motion
          → This returns reliable=False ALWAYS for stationary users

Line 450: if residual_energy <= 0.0:
          → No parallax detected (user not rotating head)
          → Returns reliable=False

CONCLUSION: For a stationary user who doesn't move their head,
motion cue ALWAYS returns reliable=False, score=0.5 (neutral).

─────────────────────────────────────────────────────────────────────────────────
BACKGROUND CUE FAILURE (source_auth/background.py)
─────────────────────────────────────────────────────────────────────────────────
FILE: source_auth/background.py

Line 133: min_frames = 3
          → Need 3 valid frames in history window
          
Line 262: reliable = valid_frames >= min_frames
          → If fewer than 3 valid frames, reliable=False
          
Frame validity requires (per frame):
  - Face size >= 40px (Line 181)
  - Inner region >= 500px (Line 201)
  - Outer region >= 500px (Line 201)

CONCLUSION: Background cue can return reliable=False if:
  - Window hasn't accumulated 3 frames yet
  - Face is too small or near edge of frame
  - Camera just started (insufficient history)

─────────────────────────────────────────────────────────────────────────────────
THE FUNDAMENTAL DESIGN FLAW
─────────────────────────────────────────────────────────────────────────────────

SourceAuth was designed for ACTIVE SURVEILLANCE scenarios:
  - People walking past a camera (lots of motion)
  - Potential attackers holding up phones (screen artifacts visible)
  - Dynamic environments with background changes

YOUR USE CASE is STATIONARY VIDEO CONFERENCING:
  - User sits still in front of camera
  - No significant head motion = motion cue fails
  - No phone/screen = screen cue returns 0 (no screen detected)
  - Consistent background = background cue returns ~0.5

RESULT: Both reliable flags are False → fusion returns UNCERTAIN.

PART 3: QUICK REFERENCE - STRICTNESS ADJUSTMENT
================================================================================

TO MAKE SYSTEM STRICTER (more rejections, fewer false accepts):
  1. INCREASE quality thresholds: 0.55 → 0.65 or higher
  2. LOWER distance thresholds: 0.35 → 0.30 for strong_dist
  3. INCREASE min_samples_strong: 3 → 5
  
TO MAKE SYSTEM MORE LENIENT (more accepts, fewer rejections):
  1. DECREASE quality thresholds: 0.55 → 0.45
  2. INCREASE distance thresholds: 0.35 → 0.40 for strong_dist
  3. DECREASE min_samples_strong: 3 → 2
